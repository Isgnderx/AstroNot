Watch one patch of sky over time: search a position and step or play through its SPHEREx observations, or compare two local files.

Find a sky position in the archive

AstroNot asks IRSA for every SPHEREx exposure that contains the position, keeps one detector, and places the observations in date order on one north-up grid, so you can step or play through them. Only the image rows around the position are read from the archive (about 1 MB per frame).

      How the sequence is built

      Search. IRSA's Simple Image Access service lists every SPHEREx level-2 exposure of the chosen detector whose footprint contains the position (at most 10000). IRSA does not let a web page read that answer, so this site forwards only that one request through its own small search service. Where the service is missing, the page gives you the IRSA link and reads the CSV you save.

      Frames. One detector is kept and its exposures are ordered by time and grouped by observing day, by visit (no gap longer than 20 days) or not at all. One frame per group is shown, six per page. With Hold one wavelength, each group's frame is the one whose wavelength at the position is closest to a reference wavelength, and a group without one within the tolerance is skipped. The reference is the wavelength inside the detector's band that the most of the first twelve groups can match. SPHEREx's filter changes wavelength across each detector, so the same star is seen at a different wavelength in every exposure; without this, most brightness changes in the animation are wavelength changes, not changes in time.

      Pixels. Only the IMAGE rows that cover the field are read, directly from IRSA's public S3 copy of the archive. Each frame is resampled bilinearly onto one north-up, east-left grid centered on the position at the native pixel scale, so every frame shows the same sky. Values stay in MJy/sr; flags, variance and the ZODI model are not applied. By default each frame's median level is subtracted for display, because the zodiacal-light background changes with the date; the table and caption values are not changed by this. This is a viewing product, not a calibrated reprojection: use Image Differencing or Forced Spectrophotometry to measure changes.

      Data: NASA/IPAC Infrared Science Archive (IRSA), SPHEREx DR1/QR3.

          How comparisons are checked

          Time comes from DATE-OBS and MJD-OBS with TIMESYS (UTC when absent). If both are present and disagree by more than a second, neither is trusted. DATE is the time the file was written and is shown separately. A time you type is marked as entered manually. Times on different time scales are not ordered.

          Same sky is decided from the WCS of each image, not from file names. Linked pan and zoom and Blink need one verified pixel grid: equal array sizes and the same sky position for sample pixels in both images. Real exposures taken on different dates usually sit on slightly different grids; the optional alignment copies the nearest comparison pixel onto the reference grid for viewing and does not interpolate or change any value. Pixel values are read from the calibrated data and do not depend on contrast.

          The same file cannot be used as two epochs: identical pixel data are rejected as the same observation. Mask, variance and other HDUs are not applied. Blink shows at most two frames per second.

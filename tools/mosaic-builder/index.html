Mosaic Builder

Combine overlapping observations into a single image of a larger sky field.

Input images

Choose two or more FITS files, or load the example pair. Files are read on this device. Each must be an uncompressed two-dimensional image with a TAN or TAN-SIP WCS in ICRS and a surface-brightness unit such as MJy/sr; all must be in the same unit (Jy prefixes such as kJy/sr are converted) and the same band. Choosing the same file and HDU again does not add it a second time; images with identical pixel values are refused as duplicates.

        Hand-off

        Download the mosaic as a FITS file: the primary HDU is the MOSAIC image (float64, NaN where invalid) with the output WCS, BUNIT, the combination mode, the resampling and every source file, observation ID and HDU (keywords and HISTORY). Extensions: MASK (0 valid, 1 invalid), COVERAGE (number of inputs with a valid value) and, when every input has variance, VARIANCE. The file opens in the FITS Viewer and in other FITS readers.

        How the mosaic is built

        Same physical quantity. Every input must have the same BUNIT, or differ only by a Jy prefix (kJy/sr and MJy/sr), which is converted with the factor shown. Values are treated as surface brightness (MJy/sr, per steradian or per angular area): they are interpolated and averaged, never summed, so the unit and the scale stay physical. Flux per pixel (Jy/pixel, counts, DN, electrons) and Jy/beam are refused, because resampling them needs an area or beam scaling that this tool does not do.

        Same band. SPHEREx cutouts carry a per-pixel wavelength table. Mosaic Builder evaluates the wavelength of two inputs at the same sky positions, not just from the file name or detector number, and refuses inputs whose wavelengths differ by more than one bandwidth. Files with a FILTER or BAND keyword must agree on it. Without either, the spectral coverage cannot be checked and this is said so.

        Output grid. By default the grid is a north-up TAN projection centred on the union of the input footprints, with the finest input pixel scale (you can set a scale and a size). Alternatively the WCS of one input can be reused, which keeps that input unresampled where it lies on the grid. Footprints are projected through each WCS, so the 0°/360° boundary, rotated inputs and different pixel scales are handled. The size and a memory estimate are checked before anything is allocated; if a limit is exceeded, a coarser scale or a smaller central field is offered.

        Resampling. Each input is resampled by bilinear interpolation at the output pixel centres through both WCS (the sampling of reproject_interp with order bilinear). This smooths the input and correlates the noise of neighbouring pixels. The four neighbouring input pixel centres must lie inside the input, so the outermost half pixel of an input is not used, and a pixel next to a NaN or masked pixel is invalid. When output pixels are more than 1.25 times larger than input pixels, several bilinear samples inside each output pixel are averaged so that fine images are not aliased.

        Combination. Mean averages the valid inputs at each pixel with equal weights. Inverse-variance weights each input by 1 / variance of the reprojected VARIANCE image and needs a variance in matching units in every input; a pixel whose variance is missing, zero or negative is left out of that average. A pixel is valid where at least one input contributes; the coverage map counts the contributing inputs, and pixels covered by none stay NaN. Only NaN and BLANK pixels are invalid in an input; FLAGS and other mask images are not interpreted. Residual background, calibration and PSF differences between exposures are not matched, so seams and steps can appear where the coverage changes.

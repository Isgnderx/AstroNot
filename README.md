# AstroNot

We’re not astronauts. We are AstroNot.

Open `index.html` in a browser to browse the local files. To use the clean URLs, run the preview server from the project folder and open [AstroNot on localhost](http://127.0.0.1:4173).

```sh
node serve.mjs
```

## Demo package

`node serve.mjs` is the local preview. To share the site, build a package that holds only the public files (the HTML pages, JS, CSS, Inter font, images and the bundled FITS examples) plus `404.html`, `.nojekyll` and `build-manifest.json`. `.git`, `tests/`, `scripts/`, `serve.mjs`, Markdown and Python files never enter it. The allowlist is `scripts/publish-rules.mjs`, and `serve.mjs` uses the same rules, so the preview serves only what ships.

```sh
node scripts/build-demo.mjs                       # dist/, for a site at the root of its host
node scripts/build-demo.mjs --base /AstroNot/     # dist/, for a GitHub Pages project site
node scripts/build-demo.mjs --out ../pages-out    # another output folder (must be empty or a previous build)
node scripts/preview-dist.mjs dist --prefix /AstroNot/ --port 4181   # emulates a static host at a subpath
```

`--base` only changes the `<base>` tag of `404.html`, because a 404 page is served at whatever depth was requested; every other page finds its assets through relative links and `routes.js`. `build-manifest.json` records the git commit (short hash), whether the working tree had uncommitted changes and which public files were among them, plus a SHA-256 per file and for the whole package, so a published demo can be matched to its source. `dist/` is git-ignored.

Checked locally with the package served at `/` and at `/AstroNot/` (as a static host would, with the folder redirect to a trailing slash) in Chrome: every route with and without a trailing slash, legacy `workspace.html?tool=…` links, reload, back and forward, a new tab, no failed or 4xx requests, Home → Show All → Tools → Sky Explorer example at 1280 px and 390 px (emulated), the FITS Viewer, Time Machine and Image Differencing examples, Observation Search preparing the IRSA link, and 404 pages at shallow and deep paths. `node --test` includes `tests/publish.test.mjs` (package contents, base validation, `serve.mjs` parity and 404).

Status: **not published.** No hosting target, visibility or permission has been chosen, so there is no shared HTTPS link yet. To publish, decide:

1. The host. GitHub Pages only publishes a branch root or `/docs`, not `/dist`, so either (a) build into a `gh-pages` branch worktree: `git worktree add ../AstroNot-pages gh-pages`, then `node scripts/build-demo.mjs --base /AstroNot/ --out ../AstroNot-pages`, commit and push there, and set Settings → Pages → Deploy from a branch → `gh-pages` / root; or (b) a GitHub Actions workflow that runs the build and uploads `dist/` as the Pages artifact. Another static host (Netlify, Cloudflare Pages, a bucket) works with the same `dist/` and `--base /`.
2. The URL path: `/AstroNot/` for `https://<user>.github.io/AstroNot/`, or `/` for a custom domain or a user site.
3. Visibility. GitHub Pages from a private repository needs a plan that allows it, and Pages sites are public to anyone with the link unless the organization restricts access.
4. Permission to push and to enable the host.

After publishing, repeat the route and Show All checks on the real HTTPS address (the Observation Search link opens IRSA, which the site cannot read from a browser, so only the prepared link is checked) and then tick the preview-link item in `TODO.md`.

## Space for Everyone

The six beginner tools are linked from `/tools#non-researcher-tools`. They use bundled assets and run in a static browser preview.

- `/tools/constellation-finder` projects 2,579 stars from the [Yale Bright Star Catalogue via NASA HEASARC](https://heasarc.gsfc.nasa.gov/W3Browse/star-catalog/bsc5p.html) onto a local sky and knows all **88 IAU constellations**: each is drawn with its official boundary (J2000 corner polygons from [d3-celestial](https://github.com/ofrohn/d3-celestial), BSD-3-Clause, after the IAU lines by Roman 1987; a test checks them against 13,238 dense boundary points — within 0.05° in the zodiac and 0.5° near the celestial poles), its name in six languages (`assets/tools/constellations.js`, generated by `scripts/make-constellations.mjs`; Azerbaijani names hand-written), its Yale stars brightened, and stick figures for the six classic shapes and the 13 zodiac constellations. The **Your zodiac sign** panel takes a birth date (1900–2100, optional time and UTC offset, otherwise 12:00 UTC) and shows two things side by side: the astrological sign (tropical zodiac, from the Sun’s apparent longitude by Meeus ch. 25, about 0.01°) and the constellation the Sun was actually in by the IAU boundaries (Ophiuchus included, with that year’s real date range); it notes when precession makes them differ and when the Sun was within half a degree of a boundary, and **Show on the sky** highlights that constellation with a marker at the Sun’s birthday position (the real Sun is not there now). The geometric horizon omits atmospheric refraction, twilight, weather and light pollution. Tests: `tests/public-zodiac.test.mjs`, `tests/constellations.test.mjs`.
- `/tools/moon-phase-calendar` shows an illuminated globe for a chosen day, with a playable phase sequence. Phase calculations follow [Paul Schlyter’s approximate lunar longitude](https://stjarnhimlen.se/comp/ppcomp.html). The calendar uses UTC and the [NASA SVS CGI Moon Kit](https://svs.gsfc.nasa.gov/4720/) surface map by Ernie Wright, derived from Lunar Reconnaissance Orbiter observations and resized for the web.
- `/tools/planet-size-comparison` uses [NASA JPL mean radii](https://ssd.jpl.nasa.gov/planets/phys_par.html) for scale. The [Solar System Scope planetary maps](https://www.solarsystemscope.com/textures/) by INOVE were resized for the web, under [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).
- `/tools/nebula-color-mixer` stacks the R and I exposures from [Digitized Sky Survey 2 via ESA/Hubble](https://esahubble.org/projects/fits_liberator/m42data/). The I image was aligned to the R image using the FITS sky coordinates. Both bands were cropped and resampled to 960 × 896, independently contrast-stretched and tinted for display.
- `/tools/meteor-shower-planner` shows typical annual peak dates and radiants from the [International Meteor Organization](https://www.imo.net/resources/calendar/). The direction is calculated for the chosen city and local time. The animation is illustrative.
- `/tools/galaxy-shape-quiz` uses four procedural 3D models to demonstrate [galaxy morphology](https://science.nasa.gov/universe/galaxies/types/).

## Scientific Tools

All thirteen tools in the directory launch a working workspace. Previous landing anchors and workspace query links continue to open their matching content.

- **Observation Search** at `/tools/observation-search` converts ICRS coordinates, UTC dates, and wavelengths into an IRSA SIA query. A **Data release** selector chooses one of five IRSA collections: SPHEREx DR1 (the default), QR3, the archived QR2, and the DR1 and QR3 deep fields (`spherex_dr1_deep`, `spherex_qr3_deep`); on 14 Nov 2026 the QR2 collection returned no rows for any position, and **Use SPHEREx example** selects DR1, where the example returns observation `2025W21_2C_0280_1` (detector 2). The importer, cutout links and the FITS Viewer hand-off accept only `dr1`, `qr3` or `qr2` level 2 products on `https://irsa.ipac.caltech.edu`. Deep-field files sit under the same `dr1/level2` and `qr3/level2` paths as the wide survey, so the importer reads each row’s `obs_collection` column to tell them apart and names them by collection (for example “SPHEREx DR1 deep fields”). The generated link opens the archive’s CSV results and asks IRSA for up to 2000 records, enough for all 239 DR1 and 113 QR3 frames of BD+17 4708. Under the imported results, **Measure these frames in Forced Spectrophotometry** opens that tool at the prepared position (`?ra=…&dec=…`). [IRSA SIA reference](https://irsa.ipac.caltech.edu/ibe/sia.html)
  - Hand-off to FITS Viewer: save the CSV from the generated link, then choose it under **Import IRSA CSV**. Each observation row (one per detector) offers **Download FITS cutout** (IRSA cutout service, centered on the search position, 0.12° by default, ICRS degrees), **Open in FITS Viewer**, and the full file. The Viewer lists the selected observation, and after you choose the downloaded file with **Choose a local FITS file** it compares the header OBSID and detector with the selected row. Only HTTPS `irsa.ipac.caltech.edu/ibe/data/spherex/qr2/level2/…fits` links are accepted. [IRSA cutout service](https://irsa.ipac.caltech.edu/data/SPHEREx/docs/cutout_tool.html)
  - Why a CSV import: on 12 Nov 2026 neither the SIA response, the full product, nor the cutout carried an `Access-Control-Allow-Origin` header, and Chrome blocked a `fetch` from a page on another origin. A page therefore cannot read them directly, and the project has no server route for it. Downloads work as ordinary navigations.
  - IRSA reports SIA errors as HTTP 200 with a VOTable even when CSV is requested, and the CSV has no overflow flag. The import shows the service message, and warns when a file holds as many rows as the 2000-record limit of the generated query. The `cloud_access` column holds unquoted JSON with commas, which the importer rejoins.
  - Tests: `node --test`. `ASTRONOT_LIVE=1 node --test tests/observation.test.mjs` also queries the real archive.
- **Sky Explorer** at `/tools/sky-explorer` opens the SPHEREx example or a local uncompressed 2D FITS image, with zoom, pan (mouse, touch, arrow keys), and a readout of the view-center and pointer RA/Dec (ICRS, degrees) and the field of view in the image area shown. Coordinates come from the image header: the primary WCS with `RA---TAN`/`DEC--TAN`, with or without `-SIP`, using `PCi_j` with `CDELTi` or `CDi_j`, `CRPIX` anywhere (including negative), and `LONPOLE`. Other projections, frames, and legacy `CROTA` headers open as pixels with RA/Dec marked Unavailable. The WCS maths is in `tools/wcs.js` and has no DOM dependency, so other tools can reuse it.
- **Time Machine** at `/tools/time-machine` compares a **Reference observation** and a **Comparison observation**, each a local uncompressed 2D FITS image HDU (the same files you download from Observation Search), or the bundled example pair. Each side shows observation ID, HDU, size, `BUNIT`, `RADESYS`, observation time, exposure, detector and, for SPHEREx cutouts that keep the `WCS-WAVE` table, the per-pixel wavelength at the image center (verified against Astropy). Observation time comes from `DATE-OBS`/`MJD-OBS` with `TIMESYS` (UTC when absent); a disagreement of more than 1 s, an unsupported scale or no time shows **Observation time unavailable**, `DATE` is shown separately as the file-written time, and a time you type is labeled **Entered manually**. The pair is checked from the WCS: sky overlap, then whether the two arrays lie on one pixel grid (same size and the same sky position for sample pixels within 0.05 px). Only a verified common grid enables linked pan/zoom and **Blink**; otherwise each panel keeps its own view and the reason is shown. Real SPHEREx exposures on different dates are usually about half a pixel apart, so the optional **Align comparison to the reference grid (display only)** copies the nearest comparison pixel onto the reference grid (no interpolation, uncovered pixels undefined) to allow Blink; it is a viewing aid, not a calibrated reprojection. Other features: shared or separate contrast range (shared only for equal units), per-panel range readout, a timeline ordered by the valid times, a marked sky point that is read from each file, **Swap roles**, and detection of the same observation used twice (identical pixel data are rejected). Blink starts stopped, offers at most 2 frames per second (1 with reduced motion), can be started with Space or B in the Blink view, and 1 or 2 pick the frame. The model is in `tools/pair.js` (no DOM) and is meant to be reused by Image Differencing.
  - Example pair: two real IRSA QR2 cutouts of one field (RA 156.09328159, Dec −41.64466331, 0.12°, detector 2): `2025W21_2C_0280_1` (2025-05-24T04:24:53 UTC) and `2025W24_1A_0514_1` (2025-06-11T14:21:56 UTC), both processed as `l2b-v20`. They keep the primary, IMAGE and WCS-WAVE HDUs in `assets/tools/spherex-time-machine-example.js`. [IRSA cutout service](https://irsa.ipac.caltech.edu/data/SPHEREx/docs/cutout_tool.html)
- **Image Differencing** at `/tools/image-differencing` computes **Δ = target − reference** for a **Reference** and a **Target** local uncompressed 2D FITS image HDU (or the bundled Time Machine example pair) and shows the reference, the target on the reference grid, and Δ with a zero-centered blue–white–red scale, a legend with the unit, and hatched invalid pixels. The sign is always labeled, and **Swap** exchanges the roles. Computation lives in `tools/difference.js` (no DOM, reusable by Motion Detector), which returns one result structure: aligned images, difference, validity and overlap masks, per-pixel status, optional variance and SNR, WCS, unit and both observation IDs (`window.AstroNotLatestDifference` holds the latest one in the page).
  - Checks before subtracting: identical units, or Jy prefixes (kJy/sr, MJy/sr) which are converted, otherwise refused with the reason (a missing BUNIT is refused unless you tick the unverified opt-in); a usable TAN/TAN-SIP WCS in both (equal array sizes alone are never accepted); overlap on the sky; the same pixel data twice is refused.
  - Grids: if every sample pixel agrees within 0.01 pixel the arrays are subtracted as they are and labeled a **pixel difference**. Otherwise the target is reprojected onto the reference grid by **bilinear interpolation** through both WCS (the method of astropy-reproject `reproject_interp` with order bilinear; values are interpolated as surface brightness). Pixels the target does not cover, or whose four interpolation neighbours include a NaN/masked pixel, stay invalid. The usable footprint ends at the outermost target pixel centers (reproject extends it by half a pixel; AstroNot does not extrapolate). Target pixels much smaller than the reference pixels are refused (aliasing). **Require one identical pixel grid** turns reprojection off. Reprojection smooths the target and correlates its noise. Real SPHEREx exposures on different dates are about half a pixel apart, so the example pair is reprojected.
  - Variance: only when both files have a VARIANCE image of the same size and matching units, Var(Δ) = Var(target) + Var(reference) for independent errors (a reprojected target contributes the sum of squared bilinear weights times variance, neighbouring pixels stay correlated); otherwise SNR is empty. No PSF matching is applied; an optional global median offset can be removed from Δ and is reported with its value. FLAGS or other mask images are not interpreted: only NaN and BLANK pixels are invalid.
  - Pixel readout: click or tap a pixel, type its FITS pixel position, or focus a view and use the arrow keys (Shift: ten pixels); the readout and the announcement give the reference value, the target value, Δ, Var(Δ), SNR, the sky position and the reason a pixel is invalid. Display range and the color limit (percentile of |Δ| or a custom value) never change the numbers. **Download difference FITS** writes DIFFERENCE (float64, NaN where invalid, reference WCS, BUNIT, `DIFFDIR`, both observation IDs), MASK (0 valid, 1 invalid) and, when available, VARIANCE.
  - Real-pair result: `2025W24_1A_0514_1` minus `2025W21_2C_0280_1` (detector 2, MJy/sr) is reprojected (largest grid offset 0.488 pixel); 4,760 of 4,900 pixels are valid, 139 lie outside the target footprint and 1 is NaN in the reference. These cutouts carry no VARIANCE image, so the SNR is unavailable there. This is a plain pixel difference without PSF or background matching.
- **FITS Viewer** at `/tools/fits-viewer` reads local FITS files in the browser and exposes each HDU’s header cards. Image previews support uncompressed 2D arrays with up to 4,194,304 pixels, a 4,096-pixel axis limit, and BITPIX values of 8, 16, 32, −32, or −64. The display applies FITS scaling and a sampled grayscale stretch. [FITS standard](https://fits.gsfc.nasa.gov/fits_standard.html)

- **Spectrum Lab** at `/tools/spectrum` opens a spectrum saved as CSV and plots flux density against wavelength with error bars, a sortable accessible table, wavelength range inputs, linear or log axes (with a disclosure of the points a log axis cannot show), Jy/mJy/µJy and µm/nm/Å conversion, and decoding of the SPHEREx Spectrophotometry flag bits. It reads the shared AstroNot spectrum columns (`wavelength` in µm, `flux` and `flux_err` in µJy, optional `lambda_width`, `flags`, `source_id`, `obs_id`, `mjd`, `ra`, `dec`, `method`) and lets you map columns and units for any other CSV. The bundled example spectrum is synthetic and labelled so; the header of the IRSA tool's own download could not be verified (it is a VOTable, which has to be converted to CSV first). [IRSA Spectrophotometry Tool](https://irsa.ipac.caltech.edu/onlinehelp/spherex/spherex/sp.html)
- **Motion Detector** at `/tools/motion` finds moving-object candidates in two to ten local 2D FITS observations of one field (or the bundled example pair): it subtracts each epoch from a chosen reference with the Image Differencing code, finds positive and negative residual peaks with a named threshold, and pairs them while rejecting registration, PSF and brightness-change residuals of static sources. For each candidate you can correct one position per epoch; RA/Dec, displacement (arcsec), position angle and, from `DATE-OBS`/`MJD-OBS`, the rate in arcsec/hour and arcsec/day are shown, with a least-squares fit for three or more epochs. It is a candidate finder, not a confirmation: on a real three-epoch SPHEREx series it listed four unverified candidates and no real moving object is claimed.
- **Spectrophotometry** at `/tools/spectrophotometry` measures the **Aperture flux density** of one ICRS position in one or more calibrated SPHEREx FITS images. It uses exact circular-aperture pixel weights and the WCS pixel solid angle, subtracts a sigma-clipped annulus background, and converts MJy/sr to µJy with `Fν[Jy] = 10⁶·Σ wᵢ(Iᵢ−b)Ωᵢ`. Wavelength comes from each file's `WCS-WAVE` table (a file without it gives a flux but no spectrum point), the uncertainty comes only from a VARIANCE image (otherwise empty), flagged pixels are left out, and the CSV uses the Spectrum Lab columns with method `aperture-photometry`. This is not the IRSA forced photometry. On a real IRSA cutout it agrees with an independent implementation to about 2e-6.
- **Forced Spectrophotometry** at `/tools/forced-spectrophotometry` measures SPHEREx spectra the way the IRSA SPHEREx Spectrophotometry Tool does: forced ePSF photometry of up to 20 ICRS positions on every level 2 frame that covers them, one spectral point per frame. It is a JavaScript port of spxphot, an independent Rust reimplementation of that tool (`tools/fits-range.js`, `tools/epsf.js`, `tools/forced-phot.js`, no DOM; the page is `tools/forced-spectrophotometry.js` with the SVG plot in `tools/forced-spectrophotometry-plot.js`). Per frame: (1) the frame list, which spxphot gets from IRSA TAP; TAP sends no CORS header, so here it comes from the SIA CSV that Observation Search builds (BD+17 4708: DR1 239 + QR3 113 = the same 352 frames), filtered by deep fields, detector and MJD; (2) only the needed bytes, by HTTP range requests to IRSA's S3 bucket (`nasa-irsa-spherex.s3.us-east-1.amazonaws.com`, which answers with `Access-Control-Allow-Origin: *`): about 25 rows of IMAGE and VARIANCE, the same rows of the RICE_1-compressed FLAGS, and the ePSF and `WCS-WAVE` tables once per detector; (3) the position by TAN-SIP (inverse-SIP guess, then Newton iteration); (4) the ePSF zone nearest the target, evaluated with a not-a-knot bicubic spline, or for a galaxy model the analytic Sérsic profile convolved with the ePSF on its 1/5-pixel lattice; (5) weighted linear least squares of the fluxes and a background in a 13-px circle, weights 1/VARIANCE, nearby targets fitted jointly; (6) µJy through the pixel solid angle, `flux = F × Ω × 10¹²`, with a 3 % systematic floor added to `flux_err`. Quality: `fit_ql` is the mean |data − model|/σ within 2.5 px, `flags` ORs the FLAGS pixels within 2.5 px plus bit 32 `CONTAINS_BAD_PIXEL` and bit 33 `FIT_ERROR`, and the wavelength is read bilinearly from `WCS-WAVE`. Results: an SVG plot (detector colours, one marker shape per target, flux_err bars, hollow markers for bits 32/33, linear or log flux axis) sharing its selection with a sortable table, a run report, an IRSA-format CSV (spxphot's 19 columns) and a Spectrum Lab CSV (method `forced-epsf`).
  - Agreement of spxphot with the IRSA tool (spxphot's validation, same inputs, matched per exposure):

    | Target | Exposures | Flux ratio (median) | Pull Δ/σ (median) | Within 1σ | Flags identical |
    |---|---|---|---|---|---|
    | BD+17 4708 (bright star) | 352 | 0.9999 | −0.02 | 84 % | 100 % |
    | WD 1657+343 (faint star) | 449 of 451 matched | 1.013 | +0.06 | 100 % | 100 % |
    | NGC 7619, Sérsic n=4, Re=5″, b/a=0.7 | 345 | 1.040 | +10.7 | 1 % | 100 % |

    Point sources are validated; the Sérsic galaxy mode is not (fluxes about 4 % high, a different spectral shape; a likely but unconfirmed cause is Tractor's Gaussian-mixture approximation of Sérsic profiles). The page says so next to the galaxy-model fields.
  - Known differences from IRSA, inherited from spxphot: wavelength median +0.0003 µm (|Δλ| ≤ 0.002 µm); `fit_ql` about 6 % higher; about 2 % of the bright-star points differ by more than 3σ, mostly on frames with near-saturation flags or `SOURCE`-flagged neighbours. The 13-px circle and the joint sky were calibrated against IRSA output, not read from IRSA's code.
  - Against spxphot itself: on the fixture cutout every output column equals a fresh spxphot run to 1e-9 relative (`fit_ql` 1e-6) with identical flags (`tests/data/spxphot/PROVENANCE.md` records how the fixture and oracle were made), and a full browser run of the BD+17 4708 example read 352 frames from S3 in about 107 s and matched spxphot's CSV on 352 of 352 rows (largest relative difference 6.4e-12).
  - Tests: `node --test`. `ASTRONOT_LIVE=1 node --test tests/forced-phot.test.mjs` also reads the first six BD+17 4708 frames from S3 and compares them with the oracle and with IRSA's rows; `ASTRONOT_LIVE_FULL=1 node --test tests/forced-phot.test.mjs` runs all 352 frames and checks the median flux ratio against IRSA. `node scripts/make-bd17-frames.mjs` regenerates the example frame list `assets/tools/spherex-bd17-frames.js` from IRSA SIA.
  - Data: NASA/IPAC Infrared Science Archive (IRSA), SPHEREx DR1/QR3. This is an independent reimplementation of the IRSA Spectrophotometry Tool's method and is not affiliated with IPAC or the SPHEREx team.
- **Source Detection** at `/tools/source-detection` finds detected candidates in one local 2D FITS image HDU (or the bundled cutout): robust background and noise (sigma-clipped median and MAD, an optional mesh, or a VARIANCE image), 8-connected pixel groups above a threshold with a minimum pixel count, optional smoothing and splitting of close peaks. Each candidate lists a flux-weighted centroid (FITS pixels, origin 1), RA/Dec from the WCS, area, peak, flux sum, S/N and edge, masked-neighbour, saturated and blended flags; markers and table rows select each other. The CSV export (`source_id,x_pixel,y_pixel,ra,dec,area_pixels,peak,flux_sum,flags,source_file,obs_id,hdu,pixel_origin`) feeds Catalog Cross-Match, and candidates are never presented as catalog identifications.
- **Light Curve Analysis** at `/tools/light-curve-analysis` plots a source's brightness against time from the Spectrophotometry CSV, from its own export, or from any table whose columns you map (ISO, JD or MJD times with a stated time scale, flux or magnitude, a unit). Series are one source in one band; plot and table share selection, gaps stay honest, and filters by series, time range and quality flags report how many rows they hide. UTC, TAI and TT convert exactly with the IERS leap-second table (to 2027-06-28), other scales and barycentric times are never mixed, and flux converts to AB magnitude with σm = 1.0857·σF/F on an inverted axis. The example is a real series of 151 aperture-photometry points measured from IRSA SPHEREx QR3 deep-field cutouts of one fixed position (not official IRSA photometry; provenance is on the page).
- **Catalog Cross-Match** at `/tools/catalog-cross-match` compares RA/Dec positions in a local CSV (such as the Source Detection export) with a Gaia DR3 or AllWISE extract saved from IRSA, listing every catalog row within a radius in arcsec (default 3, inclusive) nearest first. Catalog IDs stay text so 19-digit Gaia IDs survive, separations use Vincenty's formula with RA wrap and pole handling, and the catalog can optionally be moved to a chosen epoch by proper motion (Gaia `pmra` already includes cos Dec). The result is labelled **Nearest candidate** (a position match, not an identification) and exports to CSV with unmatched rows, radius, epochs and coverage. The bundled example is real IRSA TAP output (40 AllWISE and 72 Gaia DR3 rows near the SPHEREx example position, fetched 13 Nov 2026) and reproduces Astropy and all 18 pairs of IRSA's Gaia DR3 × AllWISE best-neighbour table; IRSA's TAP service sends no CORS header, so AstroNot cannot fetch extracts itself.
- **Mosaic Builder** at `/tools/mosaic-builder` combines two or more local 2D FITS image HDUs (or the bundled example pair) onto one north-up TAN grid. It refuses duplicates, different bands (SPHEREx wavelength is compared at the same sky positions) and incompatible units (only Jy prefixes are converted; values are treated as surface brightness and never summed), checks the output size and a memory limit before building, and reprojects each input bilinearly. Inputs are combined as an equal-weight or inverse-variance mean with a coverage map and a validity mask (uncovered pixels stay NaN), and the result exports as FITS (`MOSAIC` with WCS and `BUNIT`, plus `MASK`, `COVERAGE` and optionally `VARIANCE`) that re-opens with the FITS reader and with Astropy. The FLAGS image is not interpreted (about 90% of pixels in real cutouts carry bit 21).

The FITS example preserves the primary and IMAGE HDUs of SPHEREx QR2 observation `2025W21_2C_0280_1`, detector 2, from a 0.12° IRSA cutout. The directory thumbnail is a grayscale rendering of that image. [Original IRSA cutout](https://irsa.ipac.caltech.edu/ibe/data/spherex/qr2/level2/2025W21_2C/l2b-v20-2025-250/2/level2_2025W21_2C_0280_1D2_spx_l2b-v20-2025-250.fits?center=156.09328159,-41.64466331&size=0.12)

## Tests

```sh
node --test
```

`tests/wcs.test.mjs` checks `tools/wcs.js` against an independent JavaScript implementation and, when Python with Astropy is installed (set `ASTRONOT_PYTHON` to choose the interpreter), against Astropy WCS on the real SPHEREx example and synthetic headers. Without Astropy those comparisons are reported as skipped. `tests/difference.test.mjs` covers `tools/difference.js` (direction, units, variance, grid decisions, reprojection, invalid pixels, background, FITS export) with synthetic arrays and the real pair; with Python that has astropy and reproject (`ASTRONOT_PYTHON`) it also compares the reprojection with `reproject_interp` and reads the export back with astropy, otherwise those checks are skipped. `tests/pair.test.mjs` covers `tools/pair.js` (observation time, overlap, grid check, duplicates, link/blink decisions, view maths, alignment, wavelength lookup) with synthetic headers and with the real example pair.

### Hero artwork

The spiral galaxy in `assets/spiral-galaxy.jpg` was generated with ImageGen. Its prompt was

> Use case: photorealistic-natural. Create a square, full-resolution astrophotography texture for an animated website hero. One magnificent loosely wound spiral galaxy, seen perfectly face-on, alone against absolutely black space. Its tiny luminous warm ivory nucleus is exactly at the center of the square, with braided charcoal dust lanes, blue-white star clouds, and sparse pale rose nebulae along two long asymmetrical arms. The visual should feel like a finely resolved deep-space telescope exposure with detailed grain and deep blacks, a concentrated white-gold heart and muted cool blue arms. The galaxy fills roughly 85% of the square, and the faint outer arms naturally fade to pure black on all edges. The empty background is pure black, with almost no detached stars. No text, symbols, diffraction spikes, frame, planets, duplicate galaxies or clouds separate from the arms.

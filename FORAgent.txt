1. WHAT ASTRONOT IS
-------------------
AstroNot ("We're not astronauts. We are AstroNot.") is a static astronomy web site built by a student
team (About page: Mehin Mashadiyeva — project manager, Aykhan Isgandarzada — system engineer and repo
owner, GitHub `Isgnderx`; Uzeyir Bayramli — ML/data; Khadija Ahmadova — backend; Jahid Mahmudzada —
frontend). It gives researchers and students browser-only tools for NASA's SPHEREx infrared survey
data as served by IRSA (NASA/IPAC Infrared Science Archive): searching observations, opening FITS
files, comparing epochs, photometry, spectra, source detection, catalog cross-matching, mosaics, and
— the newest tool — forced ePSF spectrophotometry that reproduces IRSA's own Spectrophotometry Tool in
the browser.

Design principles that every tool follows:
- Everything runs client-side. There is no server, no database, no build step. Files the user chooses
  are read on their device and never uploaded.
- Honest output: every refusal has a reason, partial results are reported as partial, nothing is
  smoothed or guessed, and results are never presented as official archive products.
- Real data, real validation: examples are real SPHEREx cutouts or real IRSA tables; numerics are
  checked against Astropy/photutils/reproject and, for the new tool, against the Rust program it ports.
- Six interface languages (en, az, tr, ru, zh, es) through a runtime catalog; Azerbaijani is the
  owner's language and was hand-translated.

2. TECHNOLOGY
-------------
- Plain HTML + CSS + JavaScript (classic scripts, no modules/bundler/framework; ES2022+ features
  are used freely). Pages are served by any static host; `node serve.mjs` is the local preview
  (default port 4173; a folder without trailing slash 301-redirects like GitHub Pages).
- Node 24 for tests and scripts: `node --test` runs everything under `tests/` (node:test + assert).
- Rust → WebAssembly kernels (`rust/crates/*`, `crate-type = cdylib`, no dependencies, plain
  `extern "C"` exports + `an_alloc/an_free`) for heavy pixel work (csv, detect, fitsdata, probe,
  reproject, xmatch). Built with `node scripts/build-wasm.mjs`; output committed as
  `tools/wasm/<name>.wasm` and `.wasm.js` (base64, works from file://). Every kernel has a JS
  fallback that is also the reference in tests. The new Forced Spectrophotometry tool is JS-only
  (network-bound, not compute-bound).
- Module convention for shared logic: an IIFE that sets `root.AstroNotXxx = api` AND
  `module.exports = api` when CommonJS is present, so the same file loads in the page and in node
  tests (`createRequire` + `require("../tools/xxx.js")`). Dependencies are reached as
  `typeof module === "object" && module.exports ? require("./y.js") : root.AstroNotY`.
  UI files (`tools/<tool>.js`) hold DOM code only; numerics live in DOM-free modules.
- Styling: `styles.css` (site), `tools/workspace.css` (tool page frame), `tools/time-machine.css`
  (shared tables/file inputs), one CSS per tool. Inter font (OFL) bundled.
- i18n: `assets/i18n/site-language.js` walks text nodes/attributes and replaces them from a catalog
  `assets/i18n/<lang>.js` = `window.AstroNotLanguage.register("az", {messages}, {templates})`.
  Keys are the exact English text (whitespace-collapsed); templates use `{}` in the key and `{0}`,
  `{1}` in the value for strings the UI builds with numbers. `?lang=az` on any URL or the picker in
  the nav selects the language (persisted in localStorage). Elements with `translate="no"` are left
  alone.
- Routing: `routes.js` (`sitePage("/tools/x")`, `siteAsset(...)`, language carry-over); tool pages
  are real folders `tools/<route>/index.html`; `tools/registry.js` lists every tool (id, route,
  name, category, description, diagram/image) and drives the home page, `/tools` directory and the
  legacy `workspace.html?tool=` redirects.
- Publishing: `scripts/publish-rules.mjs` is the allowlist of what ships (root files, `assets/`,
  `tools/`, `explore/`, `learn/`, `about/`; extensions .html .css .js .svg .jpg .png .woff2 .wasm
  .txt). `scripts/build-demo.mjs` builds `dist/` (+404.html, .nojekyll, build-manifest.json with
  per-file SHA-256); `scripts/preview-dist.mjs` emulates a subpath host. `tests/publish.test.mjs`
  checks package contents and serve.mjs parity. `tests/`, `scripts/`, `.md`, `.py`, `.git` never
  ship. CSV files cannot ship (no content type) — bundled data goes in as a `.js` global.
- Python is optional: some tests compare against Astropy/photutils/reproject when
  `ASTRONOT_PYTHON` points to an interpreter that has them; otherwise those tests are skipped
  (12 skips are normal).
- Git on Windows: `core.autocrlf=true`; binary fixtures are protected by
  `tests/data/spxphot/.gitattributes` (`* -text`). Line endings in files are LF.

4. THE TOOLS (routes under /tools/)
-----------------------------------
Observation: sky-explorer (pan/zoom a SPHEREx image, RA/Dec from WCS), time-machine (compare two
epochs, blink, timeline, display-only alignment), spectrum (Spectrum Lab: plot a spectrum CSV with
units/errors/flags), observation-search (builds an IRSA SIA query link for SPHEREx DR1/QR3/QR2 and
the deep-field collections; imports the returned CSV; hands off to FITS Viewer and to Forced
Spectrophotometry — IRSA sends no CORS headers, so the page cannot fetch SIA/TAP itself).
Analysis: motion (moving-object candidates across epochs), spectrophotometry (aperture flux density
at one position in local calibrated images — NOT the IRSA method), forced-spectrophotometry (NEW:
the IRSA method, see §6), source-detection, light-curve-analysis, catalog-cross-match (Gaia DR3 /
AllWISE extracts).
Processing: fits-viewer (local FITS, headers, HDUs), image-differencing, mosaic-builder.
Non-researcher entries (constellation finder etc.) are directory cards only.
README.md has one paragraph per tool with the exact method, limits, examples and test files.

Data facts that shape the tools (verified on the dates given):
- IRSA SIA/TAP/cutout services send no Access-Control-Allow-Origin header (12–14 Nov 2026), so a
  browser page cannot read them; users save the CSV from the prepared link and import it.
- IRSA's public S3 bucket https://nasa-irsa-spherex.s3.us-east-1.amazonaws.com/ DOES send
  `Access-Control-Allow-Origin: *`, allows `Range`, and answers 206 (14 Nov 2026). This is what makes
  Forced Spectrophotometry possible client-side.
- A SPHEREx Level-2 frame (~70 MB) has HDUs PRIMARY, IMAGE (float32 2040×2040, MJy/sr, TAN-SIP),
  FLAGS (RICE_1 tile-compressed int32, one tile per row), VARIANCE, ZODI, EPSF (BINTABLE, 441 zones
  of 33×33 at 5× oversampling, ~3.86 MB), WCS-WAVE (-TAB wavelength lookup). IRSA cutouts keep EPSF
  and WCS-WAVE and store FLAGS decompressed. The site's bundled QR2 example cutouts keep only
  IMAGE (+WCS-WAVE), so they have no EPSF.
- The IRSA cutout service often answers 503 under parallel load.
